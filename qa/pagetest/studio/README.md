# Studio page tests

Headless WebKit tests for `studio/studio.html` against an export of the studio's database (default `qa/pagetest/export`).
Nothing is read from or written to a live database.

| File | What it is |
|---|---|
| `mkstudio.py` | Builds the harnesses (in `$TMPDIR/atlas_studio_test/<tag>`), among them `empty.html` (an empty store) and `claude.html` (the export plus Claude's ratings and Looks · Use). The studio's own store mock covers `doc().onSnapshot`, `collection().orderBy().onSnapshot`, `add` and `get`, and records every write in `window.__writes`. `screens.json` is served through `fetch`, and `--pics` inlines small pictures. It uses `../mkharness.py` for loading the export. |
| `prelude.js` | The helpers each test gets: `ready`, `tabTo`, `S()` (the page's `promptFor`, `cfg`, `good` and `starMap`, exposed by one line the harness adds), `tapAt`, `type`, `wideEls`, `bad`. |
| `run.sh` | `run.sh <harness> <w> <h> <light\|dark> <test.js>…` runs tests with this prelude. |
| `tests/` | `smoke` (every tab), `words` (on/off round trip, held words stay held and From pool 5 draws the same, drag, add, remove in two taps), `rate` (stars write `studio/ranks`, gold dot = 4★+, Show › No stars), `improve` (the one Improve field; emptied, the request stays with empty text, no badge, no count, its thread in the Inbox; written again, open again; Well/Badly, notes and Questions gone), `parts` (parts behind + part; Good screens from the Good tab), `screens_ui` (toolbar, ⋯ on categories and cards, the Engine group, the views), `hash` (`#screen=`), `readonly` (no store, failing writes), and more: `inbox` (a Re-envision request through the Inbox: note, done, delete, undo), `words_more` (Alt+arrows, editing a word, a held word renamed stays held, a rename to another word's name refused, adding one that is there, a colour of your own), `engine` (the Engine group rated like any screen), `hash_more` (`#screen=` after load, Escape, a folder screen), `good` (the Good tab: fill by Tiers, the two numbers from your stars beside the intro), `empty` (an empty store), `claude` (Claude's ratings and Looks · Use behind ⋯; the Tiers and Looks vs use views). |
| `all.sh` | Runs everything at 375×812 and 1280×900, light and dark. `check.py` then prints `== Studio checks: N passed, M failed`. Takes about 4 minutes. |
| `shots.sh` | Screenshots of every tab, the large view and the ⋯ panels, saved to `shots/` (pngs are kept out of git). |
| `proofs.sh` | `proofs.sh OLD.html [EXPORT] [BATCH] [LINE]`: every proof below in one run (about 7 minutes), ending `== Studio proofs: N hold, M fail`. OLD.html is the reference page the proofs compare with: `studio_before.html` beside this script. The prompt dumps go to `proof/`. |
| `prompt_proof.py` | `prompt_proof.py BEFORE.json AFTER.json [good.json] [--expect LINE]`: every part of every mix's prompt is byte-identical, except Good screens, which must be the Good tab's share titles (and, with `--expect`, read exactly LINE). Make the inputs with `tests/prompts_dump.js` run against an old and a new harness (`mkstudio.py OLD.html --tag orig`). |
| `afterbatch.py` | `afterbatch.py EXPORT BATCH.json OUT [--expect studio/good=FILE]`: the export as it will be after a batch plan (pins checked against `versions.json`, `update` merged as ArtifactData does), so the new page can be proved on it. |
| `writeback_proof.sh` | `writeback_proof.sh OLD.html [EXPORT]`: the config this page writes after Words edits (`tests/writeback_dump.js`: words on and off, held words on and off, a word edited to itself, a held word renamed and back and dragged, a pair on hold and back, a colour), read by the old page, gives the old page's prompts byte for byte, and the held words stay held (the written `poolHold` must equal the export's `poolHold` plus its set entries left off, checked against the export, not the page's chips). The other half of the Words proof: `prompt_proof.py` checks what the new page reads, this checks what it writes. |
| `variants.py` | `variants.py [EXPORT] OUT`: config variants for the write-back proof: as it is, From pool 3, 9 (and a mix D at 4), 6 with set entries left off, 4 with holds. On 9 Oct the page before the fix drew other words in `setoff` and `formsheld` (it emptied `poolHold`); `pool3` and `pool9` happened to draw the same words either way, so the `poolHold` check above now fails that page on every variant. |
| `trad/` | The Traditions header check (`header.js`) and snapshot (`snap.js`). Harness: `../mkharness.py plan/traditions.html qa/pagetest/export OUT --db trad`. |
